# ADR 0001: Процесс разработки с AI

- Статус: Принято для шаблона
- Дата: 2026-10-12
- Область: организация разработки, без выбора стека продукта

## Контекст

Нужна воспроизводимая стартовая основа для новых проектов, чтобы требования, архитектурные решения и проверки не зависели от сохранённого чата.

## Решение

Включить официальный GitHub Spec Kit с локальными skills Codex и дополнить его правилами BDD/TDD, документом System Design и журналом ADR. Полный цикл использовать для существенных функций, сокращённый — для локальных исправлений. Требования и решения хранить рядом с кодом.

## Альтернативы

- Только чат: быстрый старт, но хуже переносимость требований и решений между сессиями.
- Собственные Markdown-шаблоны: меньше сторонних файлов, но нужно самостоятельно поддерживать команды и процесс SDD.
- Одинаковый полный процесс для каждой правки: проще формально проверять, но избыточен для небольших изменений.

## Последствия

- Новый проект получает постоянные инструкции и структуру документов.
- Официальные skills и скрипты требуют контролируемых обновлений.
- Документацию нужно поддерживать вместе с реализацией.
- До начала приложения нужно определить продукт, стек, тестовый runner и CI.
- Процесс помогает проверять результат, но не гарантирует правильность требований или кода.

## Проверка

Новый проект можно создать из репозитория-шаблона, прочитать `START-HERE.md` и пройти от идеи до проверенной реализации без обращения к исходному чату.
