# Архитектурные решения — ADR

ADR нужен для выбора, влияющего на устройство системы, данные, эксплуатацию или дальнейшие изменения. Для небольшого рефакторинга он не обязателен.

1. Скопируй [шаблон](../templates/adr.md) в `docs/adr/NNNN-short-name.md` со следующим свободным номером.
2. Опиши контекст, реальные альтернативы, решение и положительные/отрицательные последствия.
3. Для ещё не принятого решения используй статус `Предложено`; после согласования — `Принято`.
4. Если решение заменено, сохрани старый ADR со статусом `Заменено` и ссылкой на новый. В новом добавь обратную ссылку.
5. Добавь запись в таблицу. При одновременном создании ADR избегай повторного номера.

| ADR | Статус | Решение |
| --- | --- | --- |
| [0001](0001-development-workflow.md) | Принято для шаблона | Spec Kit и соразмерный процесс SDD / BDD / TDD / System Design / ADR |

Новый проект наследует решение о процессе. Оно не означает, что уже выбраны БД, архитектура приложения или разрешён деплой.
