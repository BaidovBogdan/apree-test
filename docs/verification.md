## Автоматические результаты

TDD red: 4 проверки контрактов упали на отсутствии ограничений; 5 API сценариев упали на 404 при отсутствии endpoints. Затем эти проверки прошли на реальном PostgreSQL.

После ревью добавлены regressions: NUL в строках, oversized HTTP body и защита тестовой schema от URL options. NUL и oversized сначала дали наблюдаемый red (success:true в схеме; HTTP 500 вместо 400/413), затем green после исправлений.

Итог: `npm test` — **5/5 contracts + 8/8 API**, `npm run typecheck` — успешно. Дополнительно 8/8 API выполнены с исходным URL `options=-c search_path=public` и `PGOPTIONS=-c search_path=public`; preflight до миграций/CRUD и проверки ledger подтвердили уникальную schema. Живые данные приложения тестами не очищаются.

Production build успешно выполнен на Windows и внутри `docker compose up --build -d`. PostgreSQL healthy, migration service exit 0, API healthy, web доступен на http://localhost:3002 (WEB_PORT=3002, чтобы не конфликтовать с dev). API readiness — 200. Повторная миграция не вносит изменений.

## Браузерные результаты

Проверено Playwright CLI на локальном приложении, затем на контейнерной production-сборке:

- AC-001/002: создание → просмотр → изменение → reload; отмена удаления и подтверждённое удаление. Данные сохраняются в PostgreSQL и видны через новый HTTP-запрос.
- AC-003: пробельный title не сохраняется, ошибка у поля; API отдельно отклоняет границы и некорректные типы.
- AC-004: открыта форма, другая HTTP-сессия меняет запись, сохранение формы получает 409; введённое описание осталось. После закрытия доступна актуальная версия.
- AC-005/006: перенос реальной мышью за handle, меню на мобильной ширине; клавиатурой Enter открывает меню и меняет статус, затем возвращает исходный статус. Touch-эмуляция hasTouch/isMobile: создание/отмена формы, сохранность черновика, вкладки, меню и просмотр по tap.
- AC-007: пустая доска и skeleton просмотрены. GET 503 имитирован browser route: при refetch остаются старые карточки; после reload показана ошибка; Retry восстанавливает данные. POST 503 оставляет форму и введённый текст. Это управляемая имитация HTTP-отказа, не остановка PostgreSQL.
- AC-008: автор проверил390/1440, независимый дизайнер360/390/1440/1920, формы полноэкранны на телефоне, horizontal overflow не найден. Видимый фокус, Escape и dirty confirmation проверены. Screenshot evidence в локальном ignored output/playwright/.
- AC-009: поиск по тексту, отсутствие результатов, сброс; фильтр высокого приоритета обновляет количества и показывает только соответствующие задачи.
- FR-007: интерфейс содержит понятные продуктовые названия действий и реальные данные задач.

Сбои503/409 создавали ожидаемые записи browser console о failed HTTP; после обычной загрузки production не наблюдалось runtime errors/warnings.

## Уточнение интерфейса: фильтры и перенос

После исходной реализации проверены исправления подписи «Приоритет», плавное скрытие всех колонок при нулевом результате и анимация смены статуса. На Chromium 1440/390/360 px подпись читается полностью, после завершения пустого поиска колонок в DOM нет, сброс возвращает доску; горизонтального переполнения нет. RAF-замеры подтвердили промежуточные высоты/прозрачность секции и позиции карточки при переносе через меню. Отдельно проверены мышь, ответ API с задержкой, HTTP 503, Escape, быстрые изменения поиска, мобильные вкладки и reduced motion. API для отказов и конкурентного удаления подменён только в браузере; существующие задачи пользователя не изменялись.

Два дополнительных независимых read-only ревью: senior frontend code/lifecycle и UI/motion. Прочитаны все изменённые строки board/task-card/CSS/package, новый drag hook целиком, связанные вызовы и contracts; lockfile проверен по происхождению и интеграции Motion. UI reviewer независимо проверил 1440/360 px, промежуточные RAF-кадры, inert уходящей секции, меню и reduced motion. Кодовый reviewer воспроизвёл P1: исчезновение задачи при refetch во время drag оставляло интерфейс заблокированным. Исправлена независимая очистка состояния и таймера, ошибки Web Animations перехватываются. Reviewer повторил исходный сценарий (управление разблокировано), Escape (0 PATCH), успешный перенос с задержкой 600 ms, отказ 503 и следующий успешный перенос; замечание закрыто, новых подтверждённых дефектов нет.

TypeScript и production build после исправления прошли на Windows и в Docker Compose. На обновлённой контейнерной сборке повторены пустой поиск/сброс, подпись фильтра, мобильная ширина 360 px (одна видимая колонка без переполнения), меню и mouse drag с задержкой API 400 ms; ошибок и предупреждений console после обычной загрузки нет. Постоянный E2E suite не добавлен; перечисленные UI-сценарии выполнены через Playwright CLI. Необязательная рекомендация переводить фокус в поиск после сброса оставлена для последующей доработки. Firefox, Safari, физический touch и экранный диктор в этом блоке не проверены.

## Компактные колонки и устранение мигания

Убраны минимальные высоты колонок 430/500/380 px и списка 240 px; пустое состояние имеет минимум 160 px. В Chromium 1680 px root зафиксировал 235 RAF-кадров при переносе с задержкой API 450 ms: один цвет основной кнопки, opacity секции 1 и фон/opacity колонок неизменны. При этом native disabled оставался действующим 173 кадра. Отступ перед кнопкой добавления 14 px, после кнопки до внешней границы 13 px (12 px padding + 1 px border). На 390 px переполнения нет.

После сборки Windows и Docker на контейнерной версии повторены desktop 1680 и mobile 360 px: те же отступы, высоты соответствуют содержимому, ошибок/предупреждений console нет. TypeScript и production build успешны. Изменений API/БД нет, ранее пройденные 13 автоматических сценариев не запускались повторно для чисто визуального изменения.

Отдельный QA-агент исследовал CRUD, границы ввода, фильтры, формы 360/390 px, keyboard, конфликты 409 и отказы 503, отмену и повторный перенос. Новых подтверждённых дефектов не нашёл. Подробный охват, ограничения fixtures и роли всех агентов — в [agent-report](agent-report.md).

Независимый code reviewer прочитал все изменённые строки board/CSS относительно сохранённого снимка и связанные drag/card/theme/API. Проверил 1680/1100/900/899/360 px, пустое состояние 160 px, Escape (377 RAF-кадров), перенос в пустую колонку с задержкой PATCH 500 ms (405 кадров, из них 191 disabled), reduced motion. Отступы и цвета стабильны, overlay и блокировка снимаются. Подтверждённых дефектов нет. Отказ PATCH отдельно проверен QA; Firefox/WebKit, forced-colors и полный screen reader в этом блоке не проверялись.

## Непроверенные риски

## Подготовка бесплатного деплоя

Добавлены netlify.toml и render.yaml, документация deployment.md и ограниченное ожидание пробуждения только для чтения списка. npm test: 18/18 (5 contracts, 8 API на изолированной локальной schema, 5 web). TypeScript и production build с NEXT_PUBLIC_API_WAKEUP=true прошли. Новый независимый reviewer прочитал все семь изменённых code/config/test файлов, связанные контракты и deployment flow; дополнительно проверил transient/permanent HTTP-ошибки, ошибки схемы, выключенный флаг, отсутствие повтора mutation и отмену активного read.

Первый Render build выявил пропуск devDependencies при NODE_ENV=production и использование глобального TypeScript. Явный --include=dev исправил сборку, NPM_FLAGS закрепляет поведение Netlify. Reviewer подтвердил исправление; повторный Render build успешен. Проверки фактической публичной версии фиксируются после завершения деплоя.

## Непроверенные риски

Реальные iOS/Android, screen reader, полный WCAG-аудит, нагрузка 1000 задач / 20 пользователей, потеря ответа после commit, аварийное завершение дерева dev-процессов Windows и внешний deployment не проверены. GitHub Actions повторяет typecheck/test/build при публикации; фактический статус запуска доступен в репозитории.

Временная остановка PostgreSQL для проверки восстановления и сохранности volume была отклонена автоматической проверкой разрешений с причиной `blocked by policy`; действие не выполнялось, эквивалентный обход не предпринимался. Проверка реальной остановки/восстановления остаётся невыполненной. HTTP failure states проверены имитацией; readiness успешен в рабочем состоянии.
