# Apree Workspace — дизайн-система

## Основа и направление

Референс: [apreeteam.com](https://www.apreeteam.com/), просмотрен 2026-10-16. Рабочее пространство наследует тёмную палитру, розовый контурный бренд и широкие заголовки. Основной экран сразу показывает работу; отдельный маркетинговый экран не нужен.

Цвета и Montserrat подтверждены CSS сайта. Benzin указан в референсе, но его лицензия для нового приложения не предоставлена: используем открытый Montserrat с усиленным начертанием и трекингом; это явная адаптация, а не точная копия шрифта. Шрифт поставляется локально через @fontsource/montserrat (OFL), без запросов к Google Fonts. SVG-знак и логотип получены с публичного сайта в рамках брендового референса; права остаются у Apree, внешняя публикация отдельно.

Розовая кнопка имеет чёрный текст: белый на #F4019E не обеспечивает 4.5:1 для мелкого текста. Статусы: серый, розовый, зелёный; всегда с текстовыми подписями. Приоритеты: голубой/низкий, янтарный/средний, розовый/высокий; цвет дублируется подписью.

Типографика: Montserrat 400/500/600/700/800. Заголовок 36–40 px desktop / 28 px mobile, карточка 14 px semibold, основной текст 14 px/1.6, метаданные 12 px. Выравнивание по левому краю, перенос непрерывных строк. Шаг отступов 4 px; основные интервалы 8/12/16/24/32.

Радиусы: 8 px у небольших элементов, 12 px карточка, 16 px панель, pill у CTA и фильтров. Бордер сообщает границы; тяжёлых теней и декоративных градиентов на карточках нет. Небольшое розовое свечение только у брендового заголовка.

## Компоновка

```text
┌─ знак Apree / Workspace ───────────── общая доска ─┐
│ Доска задач                         + Новая задача │
│ Работа команды, от идеи до результата.             │
│ Поиск по задачам              Приоритет / Сбросить │
├─ Новая (n) ──────┬─ В работе (n) ──┬─ Готово (n) ─┤
│ карточка         │ карточка        │ карточка       │
│ + Добавить       │ + Добавить      │ + Добавить     │
└──────────────────┴─────────────────┴───────────────┘
```

Максимальная ширина 1600 px, поля 40 px на desktop / 16 px mobile. От 900 px три равные колонки. Ниже 900 px — вкладки статусов с количеством и одна колонка во всю ширину. Форма по центру до 560 px, на телефоне диалог во весь экран. Просмотр открывает полное описание и явное действие редактирования. В карточке: приоритет, кнопка меню, название, сокращённое описание, дата и ручка переноса.

Высота колонок определяется содержимым без минимального растягивания списка. Кнопка добавления идёт через 14 px после последней карточки; нижний внутренний отступ 12 px. Пустое состояние компактное, минимум 160 px. Во время завершения drag кнопки сохраняют цвет при действующей native-блокировке; drop target обозначается границей без вспышки фона.

## Поведение и доступность

- Создание и сохранение: явные подписи, disabled при запросе, ошибка рядом с формой; данные не исчезают при отказе.
- Перенос: ручка мышью, меню с тремя статусами для touch и клавиатуры. Колонка подсвечивает drop target. Нет обязательной точной моторики.
- Удаление: отдельное подтверждение с названием задачи.
- Закрытие изменённой формы: запрос подтверждения потери введённых данных.
- Loading: скелетоны вместо фиктивных задач. Empty: короткое объяснение и создание. Filter empty: отдельное состояние со сбросом поиска, три колонки скрыты. Error: причина на понятном уровне и повтор.
- Фокус 2 px розовый с отступом, цели действий минимум 40–44 px. Диалоги MUI управляют фокусом и Escape. Изменения статуса озвучиваются через live region.
- Анимации только в ответ на действия: смена мобильной колонки 180 ms, скрытие/возврат доски и пустого результата 220 ms, перемещение через меню 280 ms, завершение drag 180 ms. Карточка сразу занимает целевое место без ожидания API; во время фоновой записи видна подпись «Сохраняем…». При ошибке карточка плавно возвращается; быстрый отказ во время landing получает обратную анимацию. Соседние карточки плавно сдвигаются. prefers-reduced-motion отключает пространственные переходы. Motion отвечает за shared layout и presence; dnd-kit — за перенос. Ограниченный по времени fallback освобождает интерфейс, если источник исчез во время переноса и dnd-kit пропустил callback анимации.
- Ни фиктивных пользователей, аватаров, дат дедлайнов, прогресса, ни неработающих разделов. Все счётчики из реальных данных.

## Проверка направления до реализации

Сохранены реальные цвета, контурный знак и форма CTA компании. Из лендинга исключены огромный hero, маркетинговая статистика и насыщенные свечения: они мешают чтению рабочих задач. Главное узнаваемое место — бренд и заголовок; остальная поверхность спокойная. Точная типографика Benzin не воспроизводится без лицензии.
