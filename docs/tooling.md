# Инструменты и обновление

## Ежедневная работа

Skills Codex (`.agents/skills/`) и файлы Spec Kit (`.specify/`) уже включены. Открой корень нового проекта в Codex. Если skill не появился, переоткрой проект; можно прямо попросить агента прочитать нужный `SKILL.md`.

Python-скриптам Spec Kit нужен Python 3.11+. Команда Python зависит от системы: обычно `python`, `python3` или `py`. На Windows установлен официальный PowerShell fallback. Приложение может использовать другой язык; Python здесь нужен инструментам Spec Kit.

На Windows запускай Python-скрипты с `-X utf8`, например `python -X utf8 .specify/scripts/python/check_prerequisites.py --json`, либо установи `PYTHONUTF8=1` для запускаемого процесса. Без этого некоторые скрипты могут падать на выводе Unicode при кодировке cp1251. Этот флаг не меняет настройки всей системы. Скрипты подготовки плана и задач требуют предварительно созданной функции.

## CLI, если он нужен

Для создания новых проектов из GitHub template CLI не обязателен. Он полезен для управления интеграциями, presets и обновлениями.

Создай отдельное виртуальное окружение с Python 3.11+:

```text
python -m venv .venv
```

Затем вызови pip этого окружения:

```text
Windows:       .venv\Scripts\python -m pip install specify-cli==1.1.3
macOS / Linux: .venv/bin/python -m pip install specify-cli==1.1.3
```

CLI: `.venv\Scripts\specify` на Windows или `.venv/bin/specify` на macOS/Linux. Активация необязательна при полном пути. Не устанавливай зависимости приложения в это инструментальное окружение, если у проекта своя схема.

## Контролируемое обновление

1. Проверь [официальные релизы](https://github.com/github/spec-kit/releases) и совместимость. Не обновляй шаблон автоматически при старте проекта.
2. Сохрани текущий снимок принятым способом. Commit и push требуют прямой команды пользователя.
3. Изучи документацию целевого релиза и `specify integration upgrade --help`. Проверь команды на временной копии проекта.
4. Сравни diff управляемых skills, скриптов и шаблонов; проверь сохранность конституции, `AGENTS.md` и адаптаций.
5. Проверь создание функции, подготовку плана и задач на временной копии. Выполни ревью границ интеграции и изменений собственного кода.
6. Обнови версию и происхождение в `THIRD-PARTY-NOTICES.md`, затем перенеси проверенные изменения.

Не используй `init --here --force` или принудительный upgrade поверх рабочего проекта без анализа того, что будет перезаписано. Git/deploy extensions и автоматические commit hooks в шаблон не включены.

Официальные источники: [Spec Kit](https://github.com/github/spec-kit), [Codex skills](https://developers.openai.com/codex/skills).
