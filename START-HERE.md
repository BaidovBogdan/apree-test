# Начало нового проекта

Открой репозиторий нового проекта в Codex и отправь запрос ниже, заменив описание идеи. Остальные вопросы агент уточнит по необходимости.

```text
Начинаем новый проект из этого шаблона.

Моя идея: <что хочу сделать, для кого и какую задачу это решает>.
Ограничения, если есть: <платформа, бюджет, сроки, интеграции, выбранный стек>.

Прочитай AGENTS.md, .specify/memory/constitution.md и docs/workflow.md.
Используй включённый GitHub Spec Kit. Если skills не отображаются,
прочитай нужный SKILL.md в .agents/skills/ и следуй ему.

Сначала:
1. Проверь, что открыт новый проект, а не сам репозиторий-шаблон.
2. Изучи файлы; не считай учебные examples требованиями продукта.
3. Уточни вопросы, без которых нельзя определить результат.
4. Заполни docs/project-brief.md: проблема, пользователи, MVP, ограничения,
   что в MVP не входит, измеримые критерии успеха и открытые вопросы.
5. Создай первую спецификацию в specs/ через speckit-specify:
   сценарии, критерии приёмки, ошибки и крайние случаи.
6. Покажи ожидаемый результат и критерии приёмки для согласования.

После согласования:
7. Предложи минимальный подходящий стек с обоснованием.
8. Подготовь план через speckit-plan, заполни System Design,
   сохрани значимые решения как ADR. Не добавляй инфраструктуру без нужды.
9. Зафиксируй реальные команды установки, запуска, тестов, lint/typecheck
   и сборки в docs/commands.md; добавь CI под выбранный стек.
10. Разбей реализацию на проверяемые задачи через speckit-tasks.
11. Используй docs/testing.md: BDD для поведения, TDD для сложной логики.
12. Запусти проверки и независимое ревью по AGENTS.md, затем converge.

Не выполняй git commit, git push, деплой и изменение живых данных
без моей прямой команды. Не выдавай незапущенные проверки за успешные.
```
